# 0018 install.sh and uninstall.sh

Status: accepted 2026-10-11, revised 2026-10-12 for portable commands,
and 2026-10-22 for Chromium's sandbox (decision 0001).

## Context

A user, or the user's agent, clones the repository on any Linux machine
and runs one command. It builds the checkout's dependencies and writes
three commands. Outside the checkout it writes nothing else but the
download caches of npm (`~/.npm`) and Electron (`~/.cache/electron`),
and, with root, what Chromium's sandbox needs (decision 0001).
`uninstall.sh` removes exactly the three commands.

## Decision

- `install.sh` checks Node.js 22.12 or newer with npm (the floor of
  Electron's downloader), and python3, make and g++ (node-pty has no
  Linux prebuild and npm compiles it). It lists every missing one at
  once, with the package manager command for the compiler and python3
  on Debian, Ubuntu, Fedora, RHEL, Arch and openSUSE, and nodejs.org's
  download page for Node.js. It installs none of them.
- It runs `npm ci` only when `package-lock.json` differs from the copy
  it stamped into `node_modules` at the last install, then Electron's own
  `install.js`, which downloads the binary once (Electron 44 fetches it
  on first use, not at npm install), then checks that Electron starts.
- It writes `claude-skins`, `codex-skins` and `skinned` into `BINDIR`,
  default `~/.local/bin`, each an exec of the same name under
  `<repo>/bin`, and warns when `BINDIR` is not on PATH.
- Every generated file's second line is the marker
  `# generated by claude-skins install.sh`.
- Install refuses to overwrite a file without the marker, and says so.
- `uninstall.sh` removes every file in `BINDIR` whose second line is the
  marker, and nothing else.
- Last, it makes Chromium's sandbox start, as decision 0001 says: where
  `electron --version` aborts, the AppArmor profile
  `/etc/apparmor.d/skindeep-electron` where AppArmor restricts user
  namespaces, else `chrome-sandbox` root-owned 4755, each by two
  commands under `sudo`. It asks for a password only on a terminal.
  Without one, or when sudo fails, it prints the two commands and exits
  1. This is the one step that runs `sudo`: root is the step's whole
  point, where a missing package is the user's to install.

## Why

The marker makes uninstall exact without a state file outside the
checkout, and it also covers wrappers an earlier version wrote under
other names. A wrapper holds the checkout's path, so a moved checkout is
repaired by running install again. Prerequisites stay the user's to
install: the system's package manager or the user's own Node.js setup
knows the machine better than a script.

## Rejected

- A list of installed files kept outside the checkout: one more file to
  keep in step.
- Symlinks into the checkout: uninstall would have to resolve each link
  to tell its own from a user's file.
- Fetching Node.js or a prebuilt pty into the checkout: dependencies
  stay out of the repository.
